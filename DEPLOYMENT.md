# Step-by-Step Deployment Guide: Free Cloud Gallery

A comprehensive, zero-to-production deployment guide for setting up your own private, serverless photo and video gallery on Cloudflare Free Tier ($0/month operating cost).

---

## Architecture Overview

```
[ Client Browser ]
   |
   +---> Cloudflare Pages (Frontend Web UI)
   |
   +---> Cloudflare Worker (API Routing, Auth, SigV4 Signer)
   |        |
   |        +---> Cloudflare D1 (SQLite Database for Metadata)
   |
   +===> Cloudflare R2 (Object Storage for Raw Photos, Videos & Thumbnails)
```

---

## Prerequisites

Before starting, ensure you have:
1. A **Cloudflare Account** (Free tier is 100% sufficient).
2. **Node.js** (version 18 or newer) installed on your computer.
3. A terminal with **Git** installed.
4. *(Optional but Recommended)* A custom domain active on Cloudflare (e.g., `yourdomain.com`). If you don't have a custom domain, you can use default `*.workers.dev` and `*.pages.dev` subdomains.

---

## Step 1: Clone the Repository & Install Wrangler

Open your terminal and clone the repository:

```bash
git clone https://github.com/diarfirman/free-cloud-gallery.git
cd free-cloud-gallery
```

Ensure Cloudflare Wrangler CLI is available (or use `npx wrangler`):

```bash
# Verify Wrangler version
npx wrangler --version

# Log in to your Cloudflare account
npx wrangler login
```

---

## Step 2: Create Cloudflare D1 Database

1. Create a new D1 database named `gallery-db`:

```bash
npx wrangler d1 create gallery-db
```

Output will display your database details:
```
✅ Successfully created DB 'gallery-db'!

[[d1_databases]]
binding = "DB"
database_name = "gallery-db"
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

2. **Copy the `database_id`** value from the output. You will need it in Step 5.

3. Initialize the database schema:

```bash
npx wrangler d1 execute gallery-db --remote --file=./schema.sql
```

This creates the `photos` and `albums` tables and adds the default `General` album.

---

## Step 3: Create Cloudflare R2 Bucket & Configure CORS

1. Create an R2 storage bucket named `gallery-photos`:

```bash
npx wrangler r2 bucket create gallery-photos
```

2. Prepare CORS configuration:
Copy `cors.example.json` to `cors.json`:

```bash
cp cors.example.json cors.json
```

Edit `cors.json` and ensure your frontend domain (or `*`) is listed under `origins`:
```json
{
  "rules": [
    {
      "allowed": {
        "origins": [
          "https://gallery.yourdomain.com",
          "https://*.pages.dev",
          "*"
        ],
        "methods": ["GET", "PUT", "HEAD"],
        "headers": ["*"]
      },
      "exposeHeaders": ["ETag"],
      "maxAgeSeconds": 3600
    }
  ]
}
```

3. Apply the CORS policy to your bucket:

```bash
npx wrangler r2 bucket cors set gallery-photos --file cors.json -y
```

---

## Step 4: Generate R2 API Token (S3 Credentials)

Direct-to-R2 upload requires S3-compatible SigV4 presigned URLs generated by the Worker.

1. Open the [Cloudflare Dashboard](https://dash.cloudflare.com/).
2. In the left sidebar, navigate to **R2** > **Manage R2 API Tokens**.
3. Click **Create API Token**.
4. Configure the token:
   - **Token Name:** `gallery-uploader`
   - **Permissions:** **Object Read & Write**
   - **Specify bucket:** Select `gallery-photos` (or apply to all buckets).
   - **TTL:** Leave blank or set according to your policy.
5. Click **Create API Token**.
6. Cloudflare will display:
   - **Access Key ID** (e.g. `546f33973d4e2453fc3ea2133bbcbbf3`)
   - **Secret Access Key** (e.g. `9a8b7c6d5e4f...`)
   - **Jurisdiction-specific endpoint** (contains your 32-character **Account ID**, e.g. `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`)
7. **Save all three values immediately** in a secure note.

---

## Step 5: Configure Worker (`wrangler.toml`) & Secrets

1. Create your active `wrangler.toml` from the template:

```bash
cp wrangler.toml.example wrangler.toml
```

2. Open `wrangler.toml` and update:
   - `database_id`: Paste the D1 database ID from Step 2.
   - `MEDIA_BASE_URL`: If you set up an R2 custom domain in Step 9 (e.g., `https://media.yourdomain.com`), put it here. Otherwise, leave it as fallback.
   - `VIEW_SECRET`: Your chosen guest passcode for viewers (e.g., `familyguest`).
   - `R2_ACCESS_KEY_ID`: Your Access Key ID from Step 4.
   - `R2_ACCOUNT_ID`: Your Cloudflare Account ID from Step 4.

3. Set your private Worker secrets securely using Wrangler:

```bash
# 1. Admin master secret for uploading, editing, and deleting media:
npx wrangler secret put UPLOAD_SECRET

# 2. R2 Secret Access Key from Step 4:
npx wrangler secret put R2_SECRET_ACCESS_KEY
```

When prompted, enter your secret values.

---

## Step 6: Deploy Backend Worker API

Deploy the Worker:

```bash
npx wrangler deploy
```

Wrangler will output the live URL of your API Worker:
```
Deployed gallery-api triggers
  https://gallery-api.<your-subdomain>.workers.dev
```

If you configured a custom route in `wrangler.toml` (e.g., `api-gallery.yourdomain.com/*`), it will be accessible on that custom domain.

Test the API endpoint:
```bash
curl -i https://<YOUR_WORKER_URL>/api/albums -H "X-API-KEY: <YOUR_VIEW_SECRET>"
```
You should receive HTTP 200 OK with `["General"]`.

---

## Step 7: Configure Frontend Client

1. Copy `public/config.example.js` to `public/config.js`:

```bash
cp public/config.example.js public/config.js
```

2. Open `public/config.js` and set your Worker API URL:

```javascript
window.GALLERY_CONFIG = {
  API_URL: "https://gallery-api.<your-subdomain>.workers.dev" // or https://api-gallery.yourdomain.com
};
```

---

## Step 8: Deploy Frontend to Cloudflare Pages

Deploy the `public/` directory to Cloudflare Pages:

```bash
npx wrangler pages deploy public --project-name gallery-frontend
```

On first run, Wrangler will create the Pages project and provide a deployment URL:
```
✨ Deployment complete! Take a peek over at https://gallery-frontend.<subdomain>.pages.dev
```

---

## Step 9: Configure Custom Domains (Recommended)

Connecting custom domains makes the gallery look professional and avoids Worker execution costs for media downloads:

1. **Frontend Domain:**
   - In Cloudflare Dashboard, go to **Workers & Pages** > **gallery-frontend** > **Custom domains**.
   - Click **Set up a domain** (e.g., `gallery.yourdomain.com`).
2. **API Domain:**
   - In Cloudflare Dashboard, go to **Workers & Pages** > **gallery-api** > **Settings** > **Triggers** > **Custom Domains**.
   - Add e.g. `api-gallery.yourdomain.com`.
3. **Media CDN Domain (Direct R2):**
   - Go to **R2** > **gallery-photos** > **Settings** > **Custom Domains**.
   - Click **Connect Domain** and enter e.g. `media.yourdomain.com`.
   - Update `MEDIA_BASE_URL` in `wrangler.toml` to `https://media.yourdomain.com` and run `npx wrangler deploy`.

---

## Step 10: Verify & Use Your Gallery

1. Open your gallery URL (`https://gallery.yourdomain.com` or your `.pages.dev` URL).
2. Enter your **`UPLOAD_SECRET`** to log in as **Admin**:
   - You will see the **Admin** badge and the floating **`+ Upload`** button.
   - Upload photos or videos to test direct-to-R2 upload with progress tracking.
   - Create albums, rename albums, or edit capture dates.
3. Test **Guest Mode**:
   - Log out by clicking **Lock**.
   - Enter your **`VIEW_SECRET`** passcode.
   - You will see the **Guest Mode** badge with read-only access and the ability to download full-resolution originals.

## Common Commands & Maintenance

### Deploy Code Updates:
```bash
# Update backend Worker
npx wrangler deploy

# Update frontend Pages
npx wrangler pages deploy public --project-name gallery-frontend
```

### Rotate Passcodes:
```bash
# Update Admin Secret
npx wrangler secret put UPLOAD_SECRET

# Update Guest Passcode
# Change VIEW_SECRET in wrangler.toml, then:
npx wrangler deploy
```

### Inspect Database:
```bash
npx wrangler d1 execute gallery-db --remote --command "SELECT COUNT(*) as media_count, SUM(size_bytes) as total_bytes FROM photos;"
```

## Troubleshooting

- **CORS Error during upload:** Ensure `cors.json` contains your frontend domain and run `npx wrangler r2 bucket cors set gallery-photos --file cors.json -y`.
- **401 Unauthorized:** Verify `X-API-KEY` matches either `UPLOAD_SECRET` (Admin) or `VIEW_SECRET` (Guest).
- **Direct upload fails with HTTP 403:** Ensure the R2 API Token created in Step 4 has **Object Read & Write** permissions on the `gallery-photos` bucket.
